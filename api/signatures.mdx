The Signatures API lets you programmatically create signature requests, track signer progress, and cancel pending workflows — all from your own application. Every request must include your API key as a Bearer token and is only available on Business and Enterprise plans.

<Note>
  **Base URL:** `https://api.aflux.io/v1`  
  All requests require the `Authorization: Bearer YOUR_API_KEY` header. API access is available on **Business** and **Enterprise** plans only.
</Note>

---

## POST /signatures

Create a new signature request and send signing invitations to one or more signers. Use the `order` field on each signer to enforce a sequential workflow, or omit it to have all signers notified in parallel.

### Request Parameters

<ParamField body="document_url" type="string" required>
  The URL of the PDF document to be signed. The document must be publicly accessible or shared with Aflux (e.g. a Google Drive share link).
</ParamField>

<ParamField body="document_name" type="string" required>
  A human-readable display name for the document shown to signers and in your dashboard.
</ParamField>

<ParamField body="signers" type="array" required>
  An ordered or unordered list of signer objects. Each object describes one recipient.

  <Expandable title="Signer object fields">
    <ParamField body="signers[].name" type="string" required>
      The signer's full name, displayed in the signing invitation email and on the audit trail.
    </ParamField>

    <ParamField body="signers[].email" type="string" required>
      The signer's email address. Aflux sends the signing invitation to this address.
    </ParamField>

    <ParamField body="signers[].order" type="integer">
      The signing order for sequential workflows. Signers with lower values are notified first. When omitted for all signers, everyone is invited in parallel.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="message" type="string">
  A custom message included in the body of the signing invitation email sent to each signer.
</ParamField>

<ParamField body="expires_at" type="string">
  An ISO 8601 datetime after which the signature request expires and can no longer be signed. Example: `2024-12-31T23:59:59Z`.
</ParamField>

### Response Fields

<ResponseField name="id" type="string">
  The unique identifier for the signature request (e.g. `sig_abc123`).
</ResponseField>

<ResponseField name="status" type="string">
  Overall request status. One of `pending`, `completed`, or `declined`.
</ResponseField>

<ResponseField name="document_name" type="string">
  The display name of the document as provided in the request.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the signature request was created.
</ResponseField>

<ResponseField name="expires_at" type="string">
  ISO 8601 expiration timestamp, or `null` if no expiration was set.
</ResponseField>

<ResponseField name="signers" type="array">
  Array of signer objects reflecting current status for each recipient.

  <Expandable title="Signer status object fields">
    <ResponseField name="signers[].name" type="string">
      The signer's full name.
    </ResponseField>

    <ResponseField name="signers[].email" type="string">
      The signer's email address.
    </ResponseField>

    <ResponseField name="signers[].status" type="string">
      The individual signer's status. One of `pending` (notified, awaiting action), `waiting` (not yet notified in a sequential flow), `signed`, or `declined`.
    </ResponseField>

    <ResponseField name="signers[].order" type="integer">
      The signing order assigned to this signer, if sequential mode was used.
    </ResponseField>
  </Expandable>
</ResponseField>

### Example Request

```bash
curl -X POST https://api.aflux.io/v1/signatures \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "document_url": "https://drive.google.com/file/d/abc123/view",
    "document_name": "Service Agreement.pdf",
    "signers": [
      { "name": "Jane Smith", "email": "jane@example.com", "order": 1 },
      { "name": "Bob Jones", "email": "bob@example.com", "order": 2 }
    ],
    "message": "Please sign the attached agreement at your earliest convenience.",
    "expires_at": "2024-12-31T23:59:59Z"
  }'
```

### Example Response

```json
{
  "id": "sig_abc123",
  "status": "pending",
  "document_name": "Service Agreement.pdf",
  "created_at": "2024-11-01T10:00:00Z",
  "expires_at": "2024-12-31T23:59:59Z",
  "signers": [
    { "name": "Jane Smith", "email": "jane@example.com", "status": "pending", "order": 1 },
    { "name": "Bob Jones", "email": "bob@example.com", "status": "waiting", "order": 2 }
  ]
}
```

<Tip>
  Bob's status is `waiting` because sequential order is enabled — Aflux will notify him automatically once Jane completes her signature.
</Tip>

## GET /signatures/\{id\}

Retrieve the full details and current signer statuses for a single signature request. Use this endpoint to poll for completion or to display live status in your application.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the signature request returned when it was created (e.g. `sig_abc123`).
</ParamField>

### Response Fields

<ResponseField name="id" type="string">
  The unique identifier for the signature request.
</ResponseField>

<ResponseField name="status" type="string">
  Overall request status: `pending`, `completed`, or `declined`.
</ResponseField>

<ResponseField name="document_name" type="string">
  The display name of the document.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the request was created.
</ResponseField>

<ResponseField name="expires_at" type="string">
  ISO 8601 expiration timestamp, or `null`.
</ResponseField>

<ResponseField name="signers" type="array">
  Full list of signer objects with individual statuses. See the signer object fields in [POST /signatures](#post-signatures) for field descriptions.
</ResponseField>

### Example Request

```bash
curl -X GET https://api.aflux.io/v1/signatures/sig_abc123 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Example Response

```json
{
  "id": "sig_abc123",
  "status": "pending",
  "document_name": "Service Agreement.pdf",
  "created_at": "2024-11-01T10:00:00Z",
  "expires_at": "2024-12-31T23:59:59Z",
  "signers": [
    { "name": "Jane Smith", "email": "jane@example.com", "status": "signed", "order": 1 },
    { "name": "Bob Jones", "email": "bob@example.com", "status": "pending", "order": 2 }
  ]
}
```

## GET /signatures

List all signature requests associated with your account, with optional filtering by status and pagination controls.

### Query Parameters

<ParamField query="status" type="string">
  Filter results by request status. Accepted values: `pending`, `completed`, `declined`. Omit to return all statuses.
</ParamField>

<ParamField query="limit" type="integer">
  Number of results to return per page. Default: `20`. Maximum: `100`.
</ParamField>

<ParamField query="offset" type="integer">
  Number of results to skip for pagination. Default: `0`. Use in combination with `limit` to page through large result sets.
</ParamField>

### Response Fields

<ResponseField name="data" type="array">
  Array of signature request objects matching the applied filters.
</ResponseField>

<ResponseField name="total" type="integer">
  Total number of signature requests matching the filter, regardless of pagination.
</ResponseField>

<ResponseField name="limit" type="integer">
  The `limit` value applied to this response.
</ResponseField>

<ResponseField name="offset" type="integer">
  The `offset` value applied to this response.
</ResponseField>

### Example Request

```bash
curl -X GET "https://api.aflux.io/v1/signatures?status=pending&limit=10&offset=0" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Example Response

```json
{
  "data": [
    {
      "id": "sig_abc123",
      "status": "pending",
      "document_name": "Service Agreement.pdf",
      "created_at": "2024-11-01T10:00:00Z",
      "expires_at": "2024-12-31T23:59:59Z"
    },
    {
      "id": "sig_def456",
      "status": "pending",
      "document_name": "NDA 2024.pdf",
      "created_at": "2024-11-02T09:00:00Z",
      "expires_at": null
    }
  ],
  "total": 2,
  "limit": 10,
  "offset": 0
}
```

## DELETE /signatures/\{id\}

Cancel a pending signature request. This immediately invalidates all signing links sent to signers and marks the request as cancelled. Completed or already-declined requests cannot be cancelled.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the signature request to cancel.
</ParamField>

### Response

Returns `204 No Content` on success with an empty response body.

<Warning>
  Cancellation is permanent. Signers who have already signed will see their signatures invalidated and will be notified by email. This action cannot be undone.
</Warning>

### Example Request

```bash
curl -X DELETE https://api.aflux.io/v1/signatures/sig_abc123 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Example Response

```
HTTP/1.1 204 No Content
```
